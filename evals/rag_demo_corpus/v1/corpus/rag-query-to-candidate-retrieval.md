# 从问题到候选片段

LearnPilot 的资料问答以用户问题为起点。系统先解析资料范围，再决定是否把追问改写成独立查询。查询改写不是每次都发生：只有会话中存在受长度限制的历史、问题包含明显的追问表达、改写功能开启且模型可用时才尝试。改写结果若引入当前问题与历史之外的新英文实体，系统会回退到原问题；模型失败也不会阻断检索。

用于检索的文本由与资料相同的 Embedding 模型编码。默认模型是 `BAAI/bge-m3`，默认从本地缓存加载，文档向量和查询向量都做 L2 归一化。向量索引使用 FAISS `IndexFlatIP`。在向量已归一化的前提下，内积排序与余弦相似度排序等价，因此返回的 score 越大表示语义越接近。

FAISS Manifest 保存模型名、模型 revision、向量维度、是否归一化、距离度量、chunk ID 映射、内容校验和、索引校验和与 index version。搜索时必须同时满足模型配置、维度和校验和契约；内容表与索引不一致时，运行时报告 stale index，而不是在旧索引上继续回答。

向量命中只保存运行时 `chunk_id` 与 score。服务随后回查 SQLite 中的 `MaterialChunk` 和 `Material`，并过滤未完成解析、进入删除流程、已归档或不在指定资料范围内的记录。最终候选包含 material ID、chunk ID、原文件名、chunk 序号、正文、页码或章节标题。这里的数据库整数 ID 是一次运行时导入的标识，不是 corpus 的稳定文档标识；离线评测必须用 manifest 中的 `document_id` 对照导入后的 Material ID。

这条链路没有独立的 cross-encoder reranker。所谓“排序辨析”只能评价现有的向量分数、稳定排序、范围过滤和后续去重选择，不能假设系统执行了第二个排序模型。
