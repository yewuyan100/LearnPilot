# 测验与批改

## Attempt

只有已发布活动能创建 Attempt。进行中的答案逐题保存，刷新或关闭页面后可恢复。提交后禁止继续编辑。提交使用 UUID `request_id` 和答案快照哈希；相同请求重放同一结果，不同内容返回冲突。

## 客观题

单选、判断使用严格值比较；多选使用集合比较，因此选项顺序不影响结果，但漏选和错选都不得分。未作答为零分。客观题完全由确定性代码批改，不调用 LLM。

## 简答题

简答题使用 `short-answer-grading-v1`，温度为 0。模型只能依据题目、参考答案、固定 Rubric、来源摘录和不可信的用户答案返回结构化结果：

- 每个 Rubric 项的命中状态与得分；
- 总得分；
- 精简反馈；
- 命中项、缺失项；
- 置信度。

系统验证 Rubric ID、单项/总分边界及聚合一致性。无效输出最多修复一次。Provider、解析或校验失败会把该答案和 Attempt 标记为失败，不会冒充零分；使用同一 request_id 和答案可重试。

## 汇总与联动

聚合器使用 Decimal 计算总分并按固定精度舍入，生成百分比、正确/错误/部分得分数量。全部题目成功批改后才完成 Attempt，并更新关联学习会话和 Activity 任务。LLM 不能直接修改总分、任务或会话状态。

完成结果返回用户答案、标准/参考答案、解析、Rubric 命中与缺失、反馈和来源快照；进行中的响应不会返回答案提示。
