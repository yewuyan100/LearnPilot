# 学习活动

## 从资料到发布

活动必须显式限定至少一份已解析、已索引的资料；课程和知识点提供学习语境，但不能替代资料边界。服务先校验课程、知识点和资料，再用知识点名称/描述、课程标题、活动标题、题型和难度构造检索查询，复用 V2 的 BGE-M3、FAISS 与 SQLite Chunk 回查。

候选 Chunk 经过相关度过滤、内容去重、单段和总字符预算后获得 `S1…Sn` 标签。文件名、页码和章节始终取自数据库；模型只能引用标签，不能声明来源元数据。

生成模型必须返回严格结构：

- `single_choice`：至少两个不重复选项，且只有一个正确选项；
- `multiple_choice`：至少两个选项和至少两个正确选项；
- `true_false`：唯一布尔答案；
- `short_answer`：参考答案和分值总和等于题目分值的 Rubric；
- 每题至少一个本次上下文中的来源；
- 题干、选项和内容哈希不得重复。

首次输出不合法时，系统只允许一次整批修复。修复仍失败时不保存 Activity 或半批题目。

## 生命周期

`draft → published → archived`

草稿可改标题、描述、题目顺序和删除题目。发布前会重新运行全量合法性校验。发布后题目、答案、Rubric 和来源固定，不允许原地修改；需要变化时创建新的 Activity。

`generation_failed` 保留为状态扩展，但当前原子生成失败不会写入残缺活动。

## 安全与快照

草稿管理响应可显示标准答案、解析和 Rubric。发布活动和进行中的 Attempt 使用安全题面，不返回这些字段。QuestionSource 仅保存长度受限的摘录；原资料删除后外键置空，历史结果仍可读并显示 `source_available=false`。

## 幂等

生成使用 UUID `request_id` 和规范化请求哈希。重复相同请求返回原草稿；相同 ID 配置不同返回冲突。数据库唯一约束与进程锁共同防止并发重复生成。
